# SKU 构成管理后台

硅基流动风格后台管理页面 —— 「商品定价中心」下与 `GPU 库存` 平级的 `SKU 构成` 菜单，用于维护父子 SKU 构成关系。

## 页面布局

自上而下四段：

1. **标题行** —— 只有页面标题
2. **操作与筛选行** —— 左侧「新增构成」按钮，中间筛选器（上级 SKU / 下级 SKU / 作用），右端「明细 / 树形」视图切换
3. **列名行** —— 表格表头
4. **数据行** —— 构成关系明细，每行一条

## 列顺序

`上级 SKU ID` → `上级 SKU Code` → `下级 SKU ID` → `下级 SKU Code` → `作用` → `数量` → `创建时间` → `更新时间` → `操作`

## 数据模型

SKU **ID 与 Code 是同一个对象的两种属性**，不可分开编辑：选中一个 SKU，ID 和 Code 同时带入。

| 字段 | 说明 |
| --- | --- |
| `parentSkuId` / `parentSkuName` | 上级 SKU 的 ID 与 Code，始终成对 |
| `childSkuId` / `childSkuName` | 下级 SKU 的 ID 与 Code，始终成对 |
| `role` | 该下级在此组合中承担的作用 |
| `qty` | 该下级在上级中的个数 |
| `createdAt` / `updatedAt` | 该条构成关系的创建 / 最近编辑时间 |

约束：

- 同一 `上级 + 下级 + 作用` 唯一。
- 上级与下级不能是同一个 SKU。
- 同一 SKU 的 ID 与 Code 在全表一一对应：同一个 Code 永远对应同一个 ID。

> 注：界面术语为 **Code**，但内部数据字段仍沿用 `parentSkuName` / `childSkuName` 命名，以兼容浏览器中已存在的 `localStorage` 数据，避免升级时丢失历史记录。

## 功能

### 新增构成

- 上级 / 下级 SKU 均通过**搜索选择**：可输入 SKU ID 或 Code，下拉候选同时显示 ID 与 Code
- 选中后进入已选态，显示 `ID + Code`，两者一并确定，无法单独修改其中一个
- 可点「更换」重新选择
- 下拉底部支持**新建 SKU**：同时录入 ID（纯数字）与 Code，创建后直接带入
- 「作用」为**下拉菜单**，共 6 个预置项：`gpu` / `cpu` / `memory` / `disk` / `network` / `accelerator`
- 「数量」为正整数

### 编辑

**只能修改「作用」与「数量」**。上级与下级 SKU 以只读方式展示（ID 与 Code 同时可见），不提供搜索框，也没有「更换」按钮。

### 其他

- **筛选**：上级 SKU 与下级 SKU 各有一个独立搜索框，各自只匹配本侧 SKU 的 ID 与 Code，两条件为 AND 关系；另有作用下拉。「重置」一次清空三项
- **SKU Code**：上下级 Code 均以蓝色链接样式显示，悬停提示「点击查看 SKU 详情」，点击弹出跳转提示（原型不实际跳转）
- **视图**：明细表格（逐行展示，无合并单元格）与树形视图切换
- **排序分页**：数量 / 创建时间 / 更新时间三列互斥排序（升序 → 降序 → 取消），每页 10 / 20 / 50 / 200 条
- **持久化**：数据存于浏览器 `localStorage`（key `sku_bom_admin_v3`），刷新不丢

## 说明

纯前端单文件实现，无构建步骤、无外部依赖，数据仅保存在本地浏览器。
若要接入真实后端，将 `state.rows` 的读写替换为 API 调用即可，数据结构已分离。

注：旧版本（v1/v2）存在 `sku_bom_admin_v1` / `sku_bom_admin_v2` 下的数据会在首次加载时自动迁移并按新模型归一化。
