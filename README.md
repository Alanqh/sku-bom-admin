# SKU 构成管理后台

硅基流动风格后台管理页面 —— 「商品定价中心」下与 `GPU 库存` 平级的 `SKU 构成` 菜单，用于维护父子 SKU 构成关系。

## 页面布局

自上而下四段：

1. **标题行** —— 页面标题 + 统计（条数 / 上级数 / 下级数 / 作用种数）+ 视图切换
2. **操作与筛选行** —— 左侧「新增构成」按钮，右侧筛选器（SKU 关键词、作用）
3. **列名行** —— 表格表头
4. **数据行** —— 构成关系明细，每行一条

## 列顺序

`上级 SKU ID` → `上级 SKU Name` → `下级 SKU ID` → `下级 SKU Name` → `作用` → `数量` → `创建时间` → `更新时间` → `操作`

## 数据模型

SKU **ID 与 Name 是同一个对象的两种属性**，不可分开编辑：选中一个 SKU，ID 和名称同时带入。

| 字段 | 说明 |
| --- | --- |
| `parentSkuId` / `parentSkuName` | 上级 SKU 的 ID 与名称，始终成对 |
| `childSkuId` / `childSkuName` | 下级 SKU 的 ID 与名称，始终成对 |
| `role` | 该下级在此组合中承担的作用 |
| `qty` | 该下级在上级中的个数 |
| `createdAt` / `updatedAt` | 该条构成关系的创建 / 最近编辑时间 |

约束：

- 同一 `上级 + 下级 + 作用` 唯一。
- 上级与下级不能是同一个 SKU。
- 同一 SKU 的 ID 与名称在全表一一对应：同一个名称永远对应同一个 ID。

## 功能

### 新增构成

- 上级 / 下级 SKU 均通过**搜索选择**：可输入 SKU ID 或名称，下拉候选同时显示 ID 与名称
- 选中后进入已选态，显示 `ID + 名称`，两者一并确定，无法单独修改其中一个
- 可点「更换」重新选择
- 下拉底部支持**新建 SKU**：同时录入 ID（纯数字）与名称，创建后直接带入
- 「作用」为**下拉菜单**，共 6 个预置项：`gpu` / `cpu` / `memory` / `disk` / `network` / `accelerator`
- 「数量」为正整数

### 编辑

**只能修改「作用」与「数量」**。上级与下级 SKU 以只读方式展示（ID 与名称同时可见），不提供搜索框，也没有「更换」按钮。

### 其他

- **筛选**：SKU 关键词（同时匹配上下级的 ID 与名称）、作用下拉；点击表格中的 SKU 名称可快速按该名称过滤
- **视图**：明细表格（逐行展示，无合并单元格）与树形视图切换
- **排序分页**：数量 / 创建时间 / 更新时间三列互斥排序（升序 → 降序 → 取消），每页 10 / 20 / 50 / 200 条
- **持久化**：数据存于浏览器 `localStorage`（key `sku_bom_admin_v3`），刷新不丢；可一键恢复示例数据

## 说明

纯前端单文件实现，无构建步骤、无外部依赖，数据仅保存在本地浏览器。
若要接入真实后端，将 `state.rows` 的读写替换为 API 调用即可，数据结构已分离。

注：旧版本（v1/v2）存在 `sku_bom_admin_v1` / `sku_bom_admin_v2` 下的数据会在首次加载时自动迁移并按新模型归一化。
